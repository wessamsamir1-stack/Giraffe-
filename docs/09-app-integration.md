## ١. التشغيل

### بالبيانات التجريبية (بدون خادم)

```bash
cd app
flutter run
```

بيشتغل عادي. كل الشاشات تفتح، والبيانات من

`lib/data/mock/`

### بالخادم

```bash
flutter run \
  --dart-define=SUPABASE_URL=https://xxxx.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=eyJhbGci...
```

**المفاتيح بتتحقن وقت البناء ومابتتخزنش في المستودع أبداً.**

مفتاح

`anon`

عام بطبيعته وآمن في التطبيق — الحماية الحقيقية من سياسات الصفوف مش من إخفاء المفتاح.

أي مفتاح تاني (`service_role` · OpenAI · بوابة الدفع) **ممنوع منعاً باتاً** يدخل التطبيق. كله من Edge Functions.

## ٢. قرار: التطبيق بيشتغل من غير خادم

كل مستودع فيه مسار احتياطي على البيانات التجريبية:

```dart
Future<List<Item>> myItems() async {
  if (!hasBackend) return Mock.myItems;
  ...
}
```

**ليه؟**

أي حد يفتح المشروع يقدر يشوف كل الشاشات ويجرّب التصميم في دقيقة، من غير ما يجهّز مشروع سوبابيز. ده بيقلل احتكاك المراجعة والتسليم بشكل كبير.

والأهم: لو الخادم وقع، التطبيق مابيقعش على شاشة بيضا.

## ٤. قواعد أمنية مطبقة في طبقة البيانات

### منع تعداد الحسابات

عند فشل الدخول، رسائل سوبابيز التفصيلية **مابتوصلش للمستخدم أبداً**. الرسالة واحدة دايماً:

`auth.err.generic`

وعند التسجيل ببريد موجود، بنرجّع **نجاح** — سوبابيز بيبعت تنبيه للمالك الأصلي.

وعند استعادة كلمة السر، الرسالة واحدة سواء البريد مسجّل أو لأ.

### الحساب مابيقررش الماتش

كل سحبة بتروح للقاعدة عبر

`record_swipe`

وهي اللي بترجّع هل حصل ماتش. لو الحساب كان في التطبيق، أي حد يقدر يتحايل عليه.

نفس المنطق مع التوافق والحدود اليومية ومستوى الثقة.

### الموقع بيتزحزح قبل ما يخرج من الجهاز

شاشة الموقع بتاخد **مركز المدينة** وتزحزحه عشوائياً في حدود كيلومتر قبل ما تحفظه. الموقع الحقيقي مابيتقاسش ومابيتخزنش أصلاً.

الاستثناء الوحيد الموثّق: **زر الطوارئ** — هناك الدقة أهم من الخصوصية.

### الملف بيتحفظ مرة واحدة

شاشة الاسم بتملأ مسودة في الذاكرة، وشاشة الموقع هي اللي بتحفظ الاتنين مع بعض. كده مانعملش صف ملف ناقص لو المستخدم قفل التطبيق في النص.

| قائمة الرغبات | ✅ إضافة وحذف وتبديل التنبيه |
| القسم | ✅ + تصفية بالقسم الفرعي |
| البحث | ✅ بالتطبيع العربي |

## ٦. الرسائل اللحظية

```dart
_client.from('messages')
  .stream(primaryKey: ['id'])
  .eq('match_id', matchId)
  .order('created_at')
```

لازم تتفعّل النسخ اللحظي للجدول في لوحة سوبابيز:

`Database → Replication → messages`

من غيرها الرسائل هتوصل بس مع كل إعادة فتح للغرفة.

## ٧. التخزين

`supabase/migrations/..001700_storage.sql`

| الدلو | الوصول | الحد |
|---|---|---|
| `avatars` | عام القراءة | 2 ميجا |
| `item-photos` | عام القراءة | 8 ميجا |
| `evidence` | **خاص تماماً** | 8 ميجا |

**قاعدة الكتابة:** مسار الملف لازم يبدأ برقم صاحبه.

```
<user_id>/<item_id>/<position>.jpg
```

السياسة بتتأكد من ده على مستوى التخزين نفسه، فالمستخدم مايقدرش يكتب ولا يمسح في مجلد حد تاني.

**ملاحظة تشغيلية:** الصور **مش بتتحذف تلقائياً** لما المنتج يتمسح. محتاجة مهمة تنظيف دورية وإلا الفاتورة بتكبر بهدوء.

## ٨. تغيير في النموذج

عنوان المنتج ووصفه بقوا **نص واحد** بدل نسختين عربي وإنجليزي.

**السبب:** ده محتوى بيكتبه المستخدم بلغته. الترجمة تخص الكتالوج (الأقسام والمدن والدول) مش محتوى الناس.

الترجمة الآلية للأوصاف مؤجلة للمرحلة التانية كميزة عرض، مش كتخزين مزدوج.
