# 13 — الإشعارات الفورية

`Push notifications`

---

## ليه دي مهمة

المطابقة بتحصل والطرف التاني مش عارف. الغرفة بتفضل مقفولة والصفقة بتموت.

يعني الإشعار هنا مش تحسين تجربة — ده بيضرب **المؤشر الرئيسي نفسه**: عدد الصفقات المكتملة.

## وليه دي خطيرة

الإشعار كمان أسرع طريقة تخسر بيها مستخدم. تطبيق بيرن كتير، أو بيرن الساعة 3 الفجر، بيتشال.

فالنظام مبني على أربع قواعد.

---

## القاعدة الأولى: صندوق صادر، مش نداء من محفّز

المحفّز على

`notifications`

بيكتب صف في

`push_outbox`

والعامل بيبعت.

**ليه مش نداء مباشر؟**

لو نادينا HTTP من جوه المحفّز، معاملة قاعدة البيانات تبقى معلّقة على خدمة برّه. وأول ما جوجل تتأخر أو ترجّع خطأ، **النشر كله بيقف** — مش الإشعارات بس.

والصندوق كمان بيدينا إعادة المحاولة والتأجيل والدمج، وكلهم مستحيلين مع النداء المباشر.

---

## القاعدة التانية: مش كل إشعار يستاهل رنة

القاعدة: **الرنة لما الطرف التاني مستني رد مني.**

| النوع | رنة؟ | ليه |
|---|---|---|
| `match` | ✅ | دي اللحظة كلها. من غيرها الغرفة بتفضل مقفولة |
| `message` | ✅ | الطرف التاني مستني رد |
| `offer` | ✅ | عرض رسمي وله مهلة |
| `meeting` | ✅ | التأخير بيضيّع وقت الطرفين |
| `wishlist` | ❌ | مفيد بس مش عاجل، وبيرن كتير |
| `nearby` | ❌ | مطفي أصلاً بشكل افتراضي |
| `review` | ❌ | مش عاجل |
| `system` | ❌ | غالباً رفض منتج — مؤلم، وماينفعش يوصل كرنة مفاجئة |

اللي مش بيرن **مابيتلغيش** — بيستنى في شاشة الإشعارات جوه التطبيق.

---

## القاعدة التالتة: ساعات الهدوء

من **11 بالليل لـ 8 الصبح** بالتوقيت المحلي، الرنة **بتتأجّل** — مابتتلغيش.

مافيش حاجة في تطبيق مقايضة تستاهل توقظ حد الساعة 3 الفجر.

### المنطقة الزمنية من الدولة

مافيش عمود منطقة زمنية على الملف الشخصي، وإضافته معناها سؤال المستخدم عن حاجة هو مش مهتم بيها.

| الدولة | الإزاحة |
|---|---|
| مصر | `UTC+2` |
| السعودية · الكويت · قطر · البحرين | `UTC+3` |
| الإمارات · عُمان | `UTC+4` |

**ملاحظة صريحة:** مصر رجّعت التوقيت الصيفي، يعني الإزاحة بتتغير ساعة في الصيف. غلطة ساعة على حدود ساعات الهدوء مقبولة — أحسن بكتير من إننا مانعملش ساعات هدوء أصلاً.

## القاعدة الرابعة: الدمج

**20 رسالة في غرفة = رنة واحدة، مش 20.**

الدمج بمفتاح:

```
message:<match_id>   ← الدمج على مستوى الغرفة
<kind>               ← لغير الرسايل
```

ولو فيه رنة مستنية بنفس المفتاح، بنحدّث نصها بدل ما نضيف واحدة جديدة. يعني الرنة بتحمل **آخر** رسالة مش أولها.

وفيه دمج تاني على مستوى الجهاز نفسه (`tag` في أندرويد و`apns-collapse-id` في iOS) — عشان لو وصلت رنتين قبل ما المستخدم يفتح، يشوف واحدة.

---

## لغة الإشعار

اللغة خاصية **الجهاز** مش المستخدم: ممكن يكون عنده موبايل بالعربي وتابلت بالإنجليزي، والرنة لازم توصل بلغة الجهاز اللي هتظهر عليه.

فبتتخزّن مع الرمز، والعامل بيختار النص لكل جهاز على حدة.

وأي لغة غير الإنجليزي بترجع للعربي — ده سوق مصر والخليج.

---

## تنظيف الرموز الميتة

أهم سطر في العامل.

لما جوجل ترجّع

`UNREGISTERED`

ده معناه إن التطبيق اتشال من الجهاز. لو مامسحناش الرمز:

- الجدول بيكبر للأبد
- كل إرسال بيضيّع نداءات على أجهزة مابقتش موجودة
- **وإحنا بنحسب إن الإشعار وصل وهو مأوصلش**

التالتة هي الأخطر، لأنها بتخبّي المشكلة.

---

## انتقال الرمز بين الحسابات

لو أحمد سجّل دخول على جهاز وسام، الرمز **لازم ينتقل**:

```sql
delete from public.push_tokens where token = p_token and user_id <> me;
```

من غير السطر ده، إشعارات وسام بتفضل توصل لجهاز فيه أحمد.

ونفس المنطق عند تسجيل الخروج — الترتيب مهم:

```dart
await push.unregisterDevice();   // الأول، والجلسة لسه شغالة
await auth.signOut();            // وبعدين
```

لو عكسنا، النداء اللي بيشيل الرمز بيبقى من غير جلسة فبيفشل.

## الحماية

`push_outbox`

**شغل خادم بحت.** مفيش صلاحية للعميل خالص — لا قراءة ولا كتابة، ومش مجرد سياسة صفوف.

| الدالة | مين ينفّذها |
|---|---|
| `push_claim_batch` | الخادم بس |
| `push_mark` | الخادم بس |
| `push_drop_token` | الخادم بس |
| `register_push_token` | المستخدم |
| `unregister_push_token` | المستخدم |

والسحب بـ

`for update skip locked`

عشان أكتر من عامل يشتغلوا مع بعض من غير ما يبعتوا نفس الرنة مرتين.

## التشغيل

### الخادم — جاهز ومختبَر

العامل مجدول كل دقيقة في

`20260727002100_cron.sql`

**من غير إعدادات فايربيز**، العامل بيعلّم الصفوف

`skipped`

مش بيفشل. ده مقصود: النظام كله لازم يشتغل قبل ما حد يفتح حساب فايربيز. ولو سبناهم

`queued`

الصندوق هيتكدّس وكل دقيقة هنحاول ونفشل تاني.

### الأسرار

```bash
supabase secrets set FCM_PROJECT_ID=your-project
supabase secrets set FCM_CLIENT_EMAIL=firebase-adminsdk-xxx@your-project.iam.gserviceaccount.com
supabase secrets set FCM_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"

supabase functions deploy send-push
```

الثلاثة دول من ملف حساب الخدمة:

`Firebase Console → Project Settings → Service accounts → Generate new private key`

### وللجدولة

```sql
alter database postgres set app.settings.functions_url =
  'https://<project>.supabase.co/functions/v1';
alter database postgres set app.settings.service_key = '<service_role_key>';
```

## التطبيق — اللي لسه ناقص وليه

`firebase_messaging`

بيتطلب مشروع فايربيز وملف

`google-services.json`

ومن غير الملف ده **بناء أندرويد بيفشل من أصله** — مش بيشتغل من غير إشعارات، بيفشل التصريف نفسه.

فلو ربطنا المكتبة دلوقتي، كل واحد يستنسخ المشروع هيلاقيه مش بيتبني لحد ما يعمل حساب فايربيز. وده تمن غالي.

### اللي موجود دلوقتي

```
lib/core/push/push_service.dart      ← الواجهة + تنفيذ فاضي + تنفيذ تجريبي
lib/data/repositories/push_repository.dart  ← التسجيل والتوجيه
```

كل الباقي **جاهز ومختبَر**: طلب الصلاحية، تسجيل الرمز، متابعة التجديد، إلغاء التسجيل عند الخروج، والتوجيه عند الضغط.

اللي ناقص هو **تنفيذ واحد** بيجيب الرمز من فايربيز.

### الخطوات لتفعيله

**١.** اعمل مشروع على فايربيز وضيف تطبيق أندرويد بالمعرّف

`com.giraffe.app`

**٢.** نزّل

`google-services.json`

وحطه في

`app/android/app/`

وللـ iOS:

`GoogleService-Info.plist`

في

`app/ios/Runner/`

**٣.** ضيف في

`pubspec.yaml`

```yaml
  firebase_core: ^3.6.0
  firebase_messaging: ^15.1.3
```

**٤.** اكتب تنفيذ

`PushService`

بالمكتبة، وبدّل المزوّد:

```dart
final pushServiceProvider =
    Provider<PushService>((ref) => FirebasePushService());
```

الواجهة أربع أعضاء بس:

`isAvailable`

و

`requestPermission`

و

`currentToken`

و

`onTokenRefresh`

و

`onOpened`
